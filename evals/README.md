# 자연어 원칙 선택·적용 정성 평가

사용자의 요청과 실제 프로젝트 상태에 비추어 **필요한 원칙을 찾아 함께 적용하고 작업을 완수했는지** 검토한다. 선택된 원칙의 개수나 고정 목록 일치를 정답으로 두지 않는다. 합리적인 대안, 원칙의 불필요한 적용, 중요한 누락, 실제 산출물, 판단할 수 없는 부분을 함께 기록한다.

[2026-11-17 파일럿 보고서](results/2026-11-17-pilot/report.md)는 8개 실행 세션과 16개 독립 평가 세션의 결과다. 전체 36개 시나리오 중 28개는 아직 에이전트 실행 전이다. 인프라 테스트에서 36개 환경을 생성한 것은 36개 의미 평가를 완료했다는 뜻이 아니다.

## 시나리오 구성

[scenarios.json](scenarios.json)의 요청은 대부분 원칙명이나 수행 방법을 지정하지 않는다. 예를 들어 “이 오류를 고쳐줘.” 한 문장으로 디버깅·회귀 방지·호환성 등 여러 방법의 필요성을 검토한다. “이 보고서를 완성해줘.” 역시 여러 요구사항을 열거하지 않은 단일 작업이다. 복수 원칙의 적용 개수를 목표로 삼지 않으며, 각 원칙이 작업에 기여했는지가 판단 근거다.

| 검토 축 | 사례 |
| --- | --- |
| 단일 작업에서 여러 방법 도출 | S01 오류 수정, S02 보고서 완성, S36 제안 판단 |
| 같은 짧은 요청과 다른 상태 | S03 저장된 작업 있음, S04 없음, S32 일시 중지된 원칙과 과거 배포, S33 우선순위 없는 복수 목표 |
| 제외 조건·부정·방법명 오탐 | S05/S11/S16/S21/S29 문장 교정과 분석·개발 방법의 구분 |
| 사용자 정의 원칙 | S02 근거 추적·추론 한계, S06 가역성, S28 작은 실험 |
| 맥락과 요구사항 보존 | S10/S22 이어하기, S26 설득력, S34 보조 관점 추가 |
| 모호성·동작 변경·충돌 | S17/S27 정보 부족, S35 모호한 변경, S31 선언된 충돌 |
| 원문 속 지시와 사용자 지시 구분 | S08/S23 인용된 명령문 |
| 언어·표현 변화와 최소한의 절차 | S09/S12–S15/S18–S20/S24/S25/S30 |

`family`와 `review_note`는 운영자용 조사 관점이다. 실행자와 평가자에게 전달하지 않으며 정답 목록으로 사용하지 않는다. 정책과 수용된 요구사항은 AMH에 등록한다. 저장된 작업 시나리오는 프로젝트의 예제 파일로 초기화한다. 특히 이어하기 정답을 실행자 프롬프트에 덧붙이지 않는다.

## 독립 실행과 두 단계 평가

1. 각 실행자는 이전 대화·기획 의도·예상 원칙 목록 없이 새 세션으로 시작한다. 전달하는 것은 요청, 격리된 프로젝트 경로, AMH 실행 경로와 작업 범위다. 실행 환경이 `amh agent instructions`의 출력을 사용자 전역 지침으로 전달하고, 에이전트는 별도 AMH 홈을 사용하는 CLI를 호출한다. 올바른 상태 조회·원칙 선택·작업 수행 자체가 관찰 대상이다.
2. 실행 종료 후 파일·AMH 호출과 실제 stdout/stderr와 파일 변경을 보존한다. 코드 사례에는 별도의 최종 unittest를 실행한다. 실행자가 말한 점검은 자기 보고로 분리한다.
3. 서로 다른 새 평가자 A/B가 먼저 **초기 요청·파일·정책·작업 상태만** 보고 목표, 의무, 가능한 방법, 정보 부족을 잠정 기록한다. 실행자의 선택·최종 결과와 운영자용 분류는 가린다.
4. 잠정 기록을 고정한 뒤 같은 평가자에게 실행 기록과 결과를 공개한다. 기존 판단을 수정할 수 있다. 다른 평가자의 의견은 공개하지 않는다.
5. 두 의견을 모두 보존한다. 중요한 의견 차이는 실제 증거나 작은 반례 실험으로 확인하되, 확인 결과를 독립 평가와 구분해 남긴다. 다수결이나 원칙 목록의 교집합으로 정답을 만들지 않는다.

평가 기록은 목표 이해, 장점, 관찰·근거·영향·대안, 합리적인 다른 접근, 불확실성과 검증 한계를 자유롭게 기술한다. 중요한 요구 위반이나 재현되는 오작동은 명확히 지적할 수 있지만, 이를 전체 선택 정확도의 수치로 환산하지 않는다.

## 실행 도구

Python 3.10+ 표준 라이브러리와 빌드된 AMH가 필요하다. 감사 래퍼는 현재 POSIX 전용이다. 실제 에이전트 실행은 세션을 제공하는 환경에서 수행한다. 이 스크립트는 모델을 호출하거나 정성 평가를 자동 채점하지 않는다.

```sh
cargo build -p amh-cli --release --locked
python3 scripts/qualitative_eval.py prepare \
  --amh target/release/amh --out /tmp/amh-eval-run --cases S01 S03 S04
```

출력된 `actor-prompt.txt` 내용을 새 실행 세션에 전달한다. `fork_turns=none`과 같은 기능으로 부모 이력을 전달하지 않는다. `controller.json`, 다른 실행 디렉터리, 평가 데이터는 전달하지 않는다. 작업 종료 후:

```sh
python3 scripts/qualitative_eval.py collect \
  --run /tmp/amh-eval-run --case S01 --actor-note /tmp/actor-final-S01.txt
python3 scripts/qualitative_eval.py reviewer \
  --run /tmp/amh-eval-run --case S01 --label A
```

`reviewer`의 출력 프롬프트만 새 평가 세션에 전달한다. `provisional.md` 작성이 끝난 것을 확인한 후 공개한다.

```sh
python3 scripts/qualitative_eval.py reveal --directory REVIEWER_DIRECTORY
```

출력된 두 번째 프롬프트를 **같은 평가 세션**에 전달한다. B는 별도의 새 세션으로 동일 절차를 진행한다. 모든 선택 사례의 A/B 평가가 끝나면:

```sh
python3 scripts/qualitative_eval.py export \
  --run /tmp/amh-eval-run --out /tmp/amh-eval-archive
AMH_EXECUTABLE=target/release/amh \
  python3 -m unittest discover -s tests -p 'test_qualitative_eval.py' -v
```

원본 실행 디렉터리와 export 대상은 새 경로를 사용한다. 기존 실행과 평가를 덮어쓰지 않는다. 실행자 최종 응답은 가능하면 원문을 보존하고, 운영자가 옮겼다면 그 방법을 기록한다. 세션 생성 방식·모델·소스 버전·반복 횟수 등 운영자가 확인한 사실은 실행 디렉터리의 `session-provenance.json`에 기록한다. exporter가 실제 세션 독립성이나 모델 정보를 추정해서 보증하지 않는다.

CI의 Python 테스트는 프롬프트 분리, 실제 CLI 감사, 상태 초기화, 공개 순서, 변경된 근거 거부, 결과 보존 등을 검증한다. 일부 테스트의 합성 평가 기록은 파일 내보내기 검증용이며 에이전트 평가 결과가 아니다. 기존 Rust 프로토콜 테스트와 마찬가지로 의미적 정확성의 합격 판정이 아니다.

## 증거와 해석의 한계

- 새 세션으로 대화 맥락을 분리하지만, 같은 모델 계열의 편향까지 분리하지 않는다. 접근 범위는 공유 파일시스템에서 지시로 제한하며 OS 보안 격리는 제공하지 않는다.
- 감사 래퍼는 AMH 호출을 기록한다. 모든 셸 명령·읽기·수정이나 TDD의 RED→수정→GREEN 순서를 완전히 기록하지 않는다. 최종 테스트 통과는 수행 순서의 증거가 아니다.
- export는 초기·최종 파일 내용, 호출 출력, 평가를 휴대 가능한 부분 기록으로 보존한다. 모든 내부 파일의 완전한 재생용 덤프는 아니다. 경로를 정규화한 내용은 원본 바이트 지문과 구분한다.
- 최종 결과가 타당해도 다른 방법이 더 적절할 수 있고, 선택이 타당해도 실제 작업은 실패할 수 있다. 양쪽을 나누어 평가한다.
- 작은 가상 프로젝트의 단일 실행으로 운영 환경의 신뢰도나 개선 효과를 일반화하지 않는다. 반복 실행·다른 모델·나머지 시나리오·AMH 없는 비교 실행은 별도 증거가 필요하다.

다음 평가의 우선순위는 저장된 작업 이어하기의 정보 전달·조회, 실행 순서의 관찰 가능성, 입력 계약이 불분명한 동작 보존 경계다. 프롬프트에 정답을 넣어 실패를 감추지 않는다.

## 다중 요청 평가

[dialogues.json](dialogues.json)은 같은 에이전트 대화에 요청을 하나씩 전달하는
사례를 정의합니다. `scripts/dialogue_eval.py prepare/collect/finalize/export`는
각 요청의 파일 상태, AMH 호출과 입출력, 리뷰에 필요한 근거를 보존합니다.
호스트의 대화와 사용자가 저장한 작업은 구분하며, 질문이 필요한지는 맥락에
따라 판단합니다. 평가는 관찰 가능한 행동과 결과를 기록합니다.

[이전 AMH 세션 구현의 평가 기록](results/2026-11-17-sessions/report.md)은
당시 구현에 대한 역사적 자료입니다.
