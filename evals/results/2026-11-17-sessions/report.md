# 세션 중심 원칙 적용 — 구현과 독립 대화 평가

요청마다 필수 Task를 만들던 기본 흐름을 세션 상태와 요청별 원칙 판단으로 변경했다. 단순 요청에는 Task ID나 별도 완료 조건이 필요하지 않다. 한 세션의 상태 파일 하나를 유지하며, 지침은 표준 출력으로 전달한다. 이 문서는 실제 구현·실행 결과이며 설계 제안서가 아니다. 저장소에 추가했던 별도 제안서는 제거했다.

## 구현과 검증 범위

- 같은 대화의 맥락·수용 조건·추론·미해결 사항을 출처와 함께 유지한다. 이전에 전달한 원칙과 현재 적용할 원칙을 구분한다.
- 이전 판단을 재사용할 수 있지만, 이전에 제외한 원칙도 새 요청에서 다시 고려한다. 전체 선택 집합에 필수 조건·범위·생명주기·의존성·충돌 검사를 적용한다.
- 기존 `compile/sync/verify --task`는 선택적 계약 경로로 유지한다. 여러 Task를 정보로 첨부할 수 있으나 첨부·저장·배포만으로 현재 의도를 확정하지 않는다.
- 프로젝트 공용 파일은 연결 지침이며, 세션별 내용으로 덮어쓰지 않는다. 세션 갱신은 버전 검사·프로젝트 잠금·단일 파일 교체를 사용한다. 변경이 없으면 쓰지 않는다.
- 새로운 대화·컨텍스트 손실 시 이전 상태와 정책 지문을 제시하지 않으면 전체 재검토와 본문 전달이 기본이다. `--refresh`를 빠뜨려도 변경분만 전달되는 경로를 막았다.

| 명시적 세션 재개 | D07·D08·D09, 기존 AMH 세션 핸들만 연결하고 이전 대화는 주지 않은 새 실행자, 총 4개 요청 |
| 실행·평가 세션 | 실행자 9개, 사례당 별도의 평가자 A/B, 총 18개 평가 세션 |

모든 사례가 최종 보강 버전에서 재실행된 것은 아니다. 이전 버전의 문제와 후속 보강의 증거를 구분해 보존했다. D07·D08·D09는 서로 다른 원본 프로젝트·정책 상태를 재개했으므로 정확도나 속도의 통제된 전후 비교 실험도 아니다. 프로토콜·저장 회귀 검사는 최종 코드에서 수행했다.

| 사례 | 실제 요청 흐름 | 근거와 평가 |
| --- | --- | --- |

| D02 | 보고서 완성 → 결론 축약 → 별도 메모 요약 | 비용이 주 관점이고 유지율이 보조라는 조건을 유지했다. 결론만 줄인 후 다른 자료 요약으로 전환했다. 원문 속 AMH 비활성화 인용을 운영 지시로 취급하지 않았다 |
| D03 | “작업을 진행해” → README 작업 명확화 → 예시 출력만 답변 | 초기 질문은 유효한 확인으로 평가됐다. 명확화 이후 README만 바꾸고 함수는 보존했다. 저장된 WORK-1의 Ada 조건은 자동 채택하지 않았으며 Alice 예시는 현재 발화 범위에서는 합리적 대안이라는 평가. WORK-1 자체를 충족했다고 주장해서는 안 됨 |
| D04 | 복수 저장 작업에서 모호한 요청 → README 예시 → 제안 검토 | 실제 Task 파일 둘이 존재하며 단순 목표 목록으로 대체하지 않았다. 임의 우선순위를 정하지 않고 확인한 뒤 주제를 전환했다. 제안 검토는 가역적 기능 플래그와 백업 없는 삭제를 구분했다. 한 번의 잘못된 root 호출과 한 번의 중복 본문 전달은 작은 절차상 비효율로 남음 |
| D05 | 문장 교정 → 비교 타당성 검토 → 검토를 반영한 문장 교정 | 교정과 비교 분석의 제외 조건을 구분했다. 비교에 필요한 원자료·기간·단위가 없어 확인 질문을 했으며 이후 다시 교정 범위로 돌아갔다. 비교 타당성이 검증됐다고 주장하지 않음 |
| D06 | 보고서 완성 → 컨트롤러의 쓰기 원칙 일시 중지 → 결론 편집 → 핵심 설명 | 정책 지문 변경으로 재검토가 요구됐다. 일시 중지된 원칙은 적용되지 않고 비용·유지율 요구는 유지됐다. 중지는 실행자가 한 변경이 아니라 평가 환경의 사건으로 별도 기록 |
| D07 | 이전 대화 없이 기존 세션에 연결해 보고서 한 문장 요약 | 최종 문장은 타당했으나 refresh를 빠뜨리고 일부 판단만 갱신했다. 오래된 메모 요약 근거가 다른 캐시 판단에 남았다. 두 평가자 모두 과정·확신의 문제와 내용상의 오류 부재를 구분했다. 최초 payload 형식 오류는 재시도로 회복 |
| D08 | 재사용 기본값 보강 후 다른 기존 세션을 새 실행자로 재개 | 첫 prepare가 refresh 없이도 full_review=true를 반환했다. 이후 명시적 refresh와 일곱 조건의 전체 평가를 거쳐 모든 적용 본문이 전달됐다. 요약은 타당함. 숫자가 없는 최종 문장에 P-TRACE를 적용한 근거는 다소 넓거나 잠정적이라는 의견과, 원자료 확인 과정에는 방어 가능하다는 의견을 함께 보존 |

| D09 | 대화 이력 없이 미해결 질문 조회 → README 설명 한 문장 추가 | AMH 상태로 기다리던 대상·결과를 답했고, 사용자 명확화 후 질문만 해소했다. 기존 예시·함수는 보존했다. 입력 봉투 구성의 재시도와 이미 받은 지문을 생략한 중복 전달은 절차상 부담으로 남음 |

질문·진행·원칙 생략에 대한 합리적인 대안을 인정했다. 특히 D03·D04 평가자들은 잠정 기록에서 저장된 Ada 조건을 현재 요구로 취급했던 가정을 실제 기록을 보고 수정했다. 이를 원칙 목록의 교집합이나 다수결 정답으로 바꾸지 않았다.

## 실제 시험에서 찾고 수정한 재개 경로

D07에서는 이전 대화가 없다고 명시했지만 실행자가 `--refresh`를 누락했다. 이전 구현은 이에 대해 full_review=false를 반환했고, P-INFERENCE만 변경한 응답을 허용했다. 나머지 판단의 이유는 앞선 ‘메모 요약’을 설명하고 있었다. 답변이 올바르더라도 현재 요청의 모든 조건을 새로 검토·전달했다는 근거는 부족했다.

수정 후에는 두 값이 현재 상태와 일치할 때만 기존 판단을 상속할 수 있다.

- 이전에 전달받아 유지 중인 세션의 `known_state` 지문
- 유지 중인 정책 카탈로그의 `known_catalog` 지문

값이 없거나 다르거나 refresh를 요구하면 전체 평가와 전체 본문 전달을 요구한다. 이 값은 호출자의 연속성 선언이며 실제 모델 기억을 인증하는 증거는 아니다. D08의 첫 prepare는 옵션이 없는데도 full_review=true였다. 최종 적용은 명시적 refresh 뒤의 전체 평가이며, 새 회귀 검사는 refresh 없이도 부분 평가·reuse가 거부되고 기존 활성 원칙 및 무조건 요구의 본문이 다시 전달되는지 확인한다.

## 미해결 질문의 보존과 해소

미해결 질문은 대화 이력에만 남겨 두지 않고 agent_question 맥락으로 저장한다. 질문이 새로운 사용자 요구사항이나 원칙이 되지는 않는다. 확인이 필요한 상태에서는 새 원칙을 적용한 작업으로 진행하지 않으며, 이후 사용자가 정보를 제공했을 때 해당 질문을 명시적으로 해소할 수 있다. 다른 주제의 성공만으로 모든 질문을 완료 처리하지 않는다.

D09는 컨트롤러가 실제 API를 통해 ‘새로운 작업’에 필요한 대상·결과 확인 질문을 초기 상태로 저장한 뒤, 이전 대화가 없는 새 실행자를 연결한 사례다. 이는 실제 과거 실행자가 질문했다고 주장하는 자료가 아니라 명시적인 초기 환경이다. 실행자는 AMH 상태로 기다리던 정보를 답하고, 사용자가 README 작업을 지정하자 예시 뒤 설명 한 문장을 추가했다. 함수는 보존했고, 해결된 질문은 제거하면서 수용한 요청은 출처를 구분해 남겼다. 세부 평가는 별도 A/B 기록을 따른다.

## 파일과 처리 부담

모든 동결된 턴에서 각 프로젝트의 세션 상태 파일은 하나였다. D07·D08·D09는 각각 기존 프로젝트의 그 파일을 재사용했다. 원래 프로젝트 초기화 파일, 의도적으로 저장해 둔 Task, 실제 보고서·예시·테스트 변경은 별개다. 요청·패킷·응답용 파일은 작업 공간에 남지 않았다. 평가용 상세 로그는 컨트롤러 영역의 시험 자료이며 제품의 기본 영구 출력에 포함하지 않았다.

D01의 문서 요청과 D05의 마지막 교정 요청에서는 실제 finish 결과가 reused_without_write였다. 별도 회귀 검사에서는 같은 판단을 재사용하는 요청 100회 동안 파일 수·상태 바이트·수정 시각·버전이 유지됐다.

같은 카탈로그/맥락을 유지한 후속 요청은 그 본문을 다시 전달하지 않았다. 예를 들어 D01의 prepare 출력은 최초 11,272바이트, 다음 요청 6,086바이트였다. 요청과 적용 범위가 다르므로 이를 통제된 절감률이나 모델 토큰 절감량으로 환산하지 않는다. 기본 흐름에는 여전히 최신성 확인과 판단 제출 호출이 있으며, 모든 호출 비용이 사라진 것은 아니다.

## 과정 증거와 접근 한계

전체 제공자 세션 로그를 직접 조회한 것은 아니다. 확보한 것은 AMH 호출의 인자·시각·실제 출력과 stdin, 기록 도구에 전달한 명령·입력·출력·전후 파일 스냅샷이다. 컨트롤러는 턴마다 별도 스냅샷과 가능한 최종 검사를 남겼다. 실행자 최종 응답은 옮겨 적은 자기 보고이며 Markdown·경로 표시를 정리했다.

D01에서는 다음 순서가 실제 기록으로 확인된다.

1. 원본 4개 테스트 중 3개 실패 — [실행 기록](D01/work/e987b3ebf53e460a8c8441c6a37d660f.json)
2. 회귀 테스트 추가 후, 구현 변경 전 6개 중 4개 실패 — [실행 기록](D01/work/ca186964562c4274a3a8ac8f35ef4cbc.json)
3. 계산식 변경 — [전후 파일 기록](D01/work/98e6545b022143dd8e2b8d83df36fafa.json)
4. 변경 후 6개 테스트 통과 — [실행 기록](D01/work/249c85fa8ae548ffaf70d74c865ebe1c.json)

따라서 단순히 최종 GREEN이나 TDD 선택만 본 이전 평가보다 과정 증거가 보강됐다. 다만 기록 도구를 거치지 않은 모든 행동까지 관찰·차단한 것은 아니며 전체 세션에 대한 무조건적인 준수 증명으로 확대하지 않는다. 서명된 감사나 OS 격리도 아니다.

## 평가 인프라의 정정

D08의 초기 평가자용 정책 필드는 원본 사례의 일시 중지 전 스냅샷을 복사하는 오류가 있었다. 실행자에게 전달된 AMH 패킷은 실제 최신 정책이었다. 잠정 평가 이후, 결과 공개 전에 동결된 레지스트리와 바이트 지문이 일치하는 현재 정책 스냅샷으로 정정 정보를 제공했다. 초기 자료와 잠정 의견은 그대로 보존했다. 두 평가자는 P-WRITING이 일시 중지된 사실을 반영해 판단을 수정했다.

[정정 근거](D08/controller-correction.json)는 원하는 원칙 집합이나 판정이 아니라 현재 레지스트리의 사실 확인이다. 후속 준비 도구는 이전 사례의 초기 정책을 복사하지 않고 실제 현재 정책을 읽도록 수정했고, 일시 중지 후 재개 스냅샷을 검사하는 회귀 테스트를 포함했다. 이 정정 이력은 초기 평가 환경이 완전히 균일했다고 주장하지 않기 위해 남긴다.

별도로, [이전 단일 요청 파일럿](../2026-11-17-pilot/report.md)의 S03을 ‘불필요한 재질문으로 확정된 P0 결함’이라고 부른 해석도 정정했다. 저장된 작업이 현재 의도라는 근거가 충분하지 않았다. 원자료·평가자 의견은 바꾸지 않았다.

## 전달 형식의 사용성 보완

D07–D09의 재시도는 간단한 질문에도 불필요한 절차를 만들 수 있음을 보여줬다. 이에 따라 최신 코드 `a381329884d958073894d34d0001cccba48c69b4`는 다음을 보완했다.

- `session finish --help`로 내부 응답과 제출 봉투 `{packet, response}`의 차이를 확인할 수 있다.
- 기존 용어 `analysis`를 `response`의 별칭으로 허용하되 둘을 동시에 제출하거나 알 수 없는 필드를 추가하면 거부한다.
- 준비 패킷의 지침과 오류 메시지에 정확한 제출 형태를 안내한다. 원래 패킷의 변경·다른 세션·오래된 상태를 허용하지 않는다.

이 마지막 보완은 CLI 회귀 검사로 확인했다. 이후 전체 에이전트 시험을 다시 수행한 것은 아니므로 재시도가 모두 사라졌다고 주장하지 않는다. 알고 있는 지문을 생략해 중복 본문을 받은 사례도 남아 있어, 문맥 재사용의 비용 효과를 모든 에이전트에서 보장하지 않는다.

## 자동 검사와 남은 범위

최종 코드에서 로컬 기본 workspace 150개, 전체 기능 154개, 최소 코어 38개 테스트가 통과했다. 평가 인프라 17개, formatting, Clippy의 warnings-denied 검사와 release 빌드도 통과했다. 부모 테스트에서 의도적으로 제외한 timeout helper 한 개는 기존 subprocess 회귀 검사에서 실행된다.

이 숫자는 의미 정확도나 사례 합격률이 아니다. 실제 평가에서 명확한 결과 오류가 없었다는 의견과 프로토콜 실수·과한 원칙 선택·미확인 영역을 함께 보존했다. 특히 D07의 과정 문제는 답변 품질만으로 놓칠 수 있었다.

같은 기본 모델 계열의 작은 합성 프로젝트, 사례당 한 번의 실행이다. 다른 모델·실제 장기 프로젝트·큰 정책 집합·AMH 없는 비교 실험은 수행하지 않았다. 초기 36개 단일 요청 시나리오 중 미실행 28개도 이 대화 시험으로 수행한 것으로 계산하지 않는다. 플랫폼의 모든 세션 ID·축약·재개 사건이나 전체 로그를 자동으로 얻는 기능은 없다. 최신성 지문과 해석의 출처는 검토 가능하지만 의미적 판단과 행동 준수는 계속 평가해야 한다.

## 원자료 읽기

- 각 Dxx의 `initial.json`: 평가자 초기 맥락. `review-A.json` / `review-B.json`: 실제 단계별 프롬프트·잠정 판단·최종 의견
- `calls.json`: 실제 AMH 호출·출력·가능한 stdin. `work/ID.json`: 기록 도구를 통과한 명령·출력·전후 파일
- `turns/N/observation.json`: 각 요청의 산출물과 자기 보고. `session-states.json`: 동결된 세션 상태. `file-inventory.json`: 실제 동결 파일 목록·크기·지문
- `deployed.md`와 observation의 `final_deployment`는 선택적 **기존 Task 어댑터**의 자료다. 현재 세션의 적용 상태는 `session-states.json`과 AMH finish 출력으로 확인한다
- D06의 `controller-event.json`: 턴 사이 정책 변경 주체. D08의 `controller-correction.json`: 초기 평가 환경 정정
- [provenance.json](provenance.json): 바이너리/시나리오·제품 버전·세션 분리·관측 한계. [manifest.json](manifest.json): 보존 자료 SHA-256

경로는 휴대 가능한 표기로 정규화했다. 기록 속 원본 파일/패킷 지문은 정규화 전 바이트에 대한 것이며, 보존 파일 자체의 지문은 manifest에서 별도로 제공한다. 이 자료는 완전한 제공자 대화 재생 덤프가 아니다.
