2026-11-22 한국 시간에 자연어 요청 네 가지를 AMH와 정적 `AGENTS.md`에서 각각 한 번 실행했다. D03과 D06은 AMH로 세 턴씩 실행했다. 실행자는 부모 이력을 받지 않은 새 세션에서 시작했다. 다중 요청의 후속 메시지는 같은 실행자에게 한 턴씩 전달했다. 두 정성 검토자가 각 평가 단위의 초기 정보를 먼저 보고 판단을 기록한 뒤, 같은 해시의 실행 근거를 받아 결과를 검토했다. 다중 요청은 턴과 평가자마다 새 검토 세션을 사용했다. 단일 요청의 두 검토자는 각각 네 사례의 두 전달 방식 모두를 검토했다.

모든 실행은 같은 기본 모델 설정을 상속했다. 정확한 모델 식별자는 확인할 수 없었다. AMH의 전역 지침은 실행 프롬프트에서 재현했고, 정적 조건의 활성 정책은 같은 적용 조건과 본문을 `AGENTS.md`에 넣었다. 정적 조건의 네 실행자 모두 기록 래퍼를 통해 파일을 읽었다. 기록에는 AMH CLI 입출력, 관찰 도구를 통해 실행한 작업, 작업 전후 파일, 운영자가 옮긴 실행자 응답이 포함된다. 호스트의 전체 세션 로그는 관찰하지 못했다.

S01의 AMH 실행에서는 같은 카탈로그를 두 번 읽었다. AMH 실행은 디버깅, 회귀, 공개 API 보존, TDD, 근거 확인을 선택했고 테스트 실패 → 구현 수정 → 테스트 통과 순서가 기록됐다. 정적 실행에서도 같은 순서를 관찰했다. 두 실행 모두 기존의 실패 테스트를 사용했다.

정성 검토 후 S01의 동결된 산출물에 0%·100% 할인 경계 검사를 추가해 별도로 다시 실행했다. AMH 실행의 구현은 100% 할인에서 가격 `0.33333333333333`에 미세한 음수를, `1e308`에 `-inf`를 반환했다. 정적 실행의 구현은 0% 할인에서 같은 소수 가격을 정확히 보존하지 못했고 `1e308`에서 `inf`를 반환했다. 두 구현 모두 보강된 독립 검사를 실패했고, 경계를 명시적으로 처리한 대조 구현은 통과했다. 원래 평가 당시의 검사 결과는 그대로 보존했다.

## 다중 요청

- **D03** 첫 턴에는 요청, 저장된 작업 한 건, README와 구현을 근거로 작업했다. 두 검토자는 사용자 메시지의 모호성이 있더라도 이 경우 직접 진행한 판단이 타당하다고 보았다. 두 번째 요청에서 사용자가 작업을 특정했을 때 추가 파일 변경이 없었고, 세 번째에는 예시 출력만 답했다. 첫 턴 평가에는 이 후속 요청들이 포함되지 않았다.
- **D06** 첫 턴에서 `P-WRITING` 본문이 전달됐다. 운영자가 다음 요청 전에 해당 정책을 일시 중지하자 카탈로그가 바뀌고 후보가 22개에서 21개로 줄었다. 실행자는 두 번째 턴에서 바뀐 카탈로그를 조회했고, 다시 전달된 지침에는 `P-WRITING`이 없었다. 결론과 권고안은 비용을 중심으로 수정됐고 유지율은 보조 지표로 남았다. 세 번째 턴은 파일 변경 없이 보고서의 핵심을 설명했다. 이전 정책의 내부 기억이나 영향은 관찰 범위에 포함되지 않는다.

이번 실행에서는 두 전달 방식 모두 요청에 맞는 접근을 보였고, S01은 두 방식 모두에서 추가 검사가 필요했다. AMH가 전달한 본문은 더 짧았지만 후보 조회까지 포함한 합계는 사례에 따라 달랐다. 한 모델 설정과 사례당 한 번의 실행으로 정책 선택 정확도나 문맥 효율을 일반화할 수 없다.
