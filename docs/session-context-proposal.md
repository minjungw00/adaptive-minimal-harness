# AMH 세션 중심 사용자 흐름 수정안

작성일: 2026-11-17 · 상태: 구현 전 제안 · 검토 기준: `4b2d45d68fac7ed7bcc9b0e242526ff818ee7798`

## 1. 목표와 범위

기존 에이전트와의 대화 세션을 맥락 유지 단위로 삼는다. 각 요청에서는 현재 요청에 필요한 원칙을 판단하되, 이미 전달한 지침과 유효한 판단을 재사용한다. 명확한 단순 요청마다 별도 Task와 완료 조건을 만드는 것을 필수로 요구하지 않는다.

사용자는 자연어로 요청한다. 세션 ID·원칙 ID·태그·명세 파일의 작성은 사용자 흐름에 추가하지 않는다. 중요한 모호성이 있을 때 필요한 확인만 한다. 원칙 선택과 재사용은 에이전트의 의미 판단이며, AMH는 이를 독립적인 정답이나 행동 준수 증명으로 취급하지 않는다.

이번 범위는 세션 상태, 원칙 선택·전달, 요청 처리, 저장·검증 및 평가의 연결이다. 새 에이전트 런너, 필수 외부 모델, 서버, DB, 작업 스케줄러는 도입하지 않는다. 업무 관리용 담당자·기한·복잡한 작업 생명주기는 별도 요구가 생기기 전까지 추가하지 않는다.

## 2. 현재 구조와 변경 방향

| 현재 확인된 구조 | 변경 방향 |
| --- | --- |
| Task는 ID·목표·비어 있지 않은 완료 조건을 필수로 요구 | 자연어 대화는 최소 세션 맥락을 사용. 명시적 작업 계약은 선택적으로 사용 |
| 자연어 해석이 요청마다 Task를 구성 | 현재 요청의 의도와 기존 상태의 관계를 해석하고 필요한 상태·원칙만 갱신 |
| 요청 원문 인용을 중심으로 판단 근거 검사 | 현재 발화와 출처가 확인되는 세션 맥락을 함께 참조하고 원본 위치를 검증 |
| AGENTS.md 브리지가 매 실질적 요청에 전체 후보 평가와 파일 입출력 지시 | 세션 연결·최신성 확인·적용 판단·필요한 갱신으로 변경 |
| 프로젝트 공용 생성 지침과 단일 배포 Task | 공용 파일은 연결 지침, 세션별 내용은 세션 전용 경로 |
| 작업에 연결된 검증 명령·증거 | 기존 Task 검증을 유지하고 필요한 경우 세션 내 특정 대상·시점에 증거 연결 |

현재 `.amh/generated/AGENTS.md`와 `.amh/deployment.json`은 고정 경로를 갱신한다. 모든 요청이 새 영구 명세 파일을 만드는 것은 아니다. 개선 대상은 반복 해석·필수 Task 구성과 프로토콜 임시 파일 생성, 선택적 검증 자료의 보존 방식이다. 파일 수뿐 아니라 호출·전달량·쓰기 횟수도 함께 측정한다.

## 3. 상태 모델

### 3.1 사용자·프로젝트 정책

기존 정식 정책 저장소와 버전·생명주기·적용 조건·관계·사용자/프로젝트 범위를 유지한다. 세션 요약이나 에이전트 추론으로 이 저장소의 정책을 수정하지 않는다.

### 3.2 세션 상태

세션 상태는 실제 원칙 선택·재사용·전달에 사용하는 기능 데이터다. 상세 대화 로그와 역할을 구분한다.

| 요소 | 목적·주의사항 |
| --- | --- |
| 프로젝트·세션 식별자 | 다른 프로젝트·세션과 연결되지 않도록 바인딩. 사용자 인증의 증명은 아님 |
| 상태 버전·정책 지문 | 오래된 상태에 대한 갱신·판단 적용 거부 |
| 논의 대상과 관련 조건 | 필요한 경우에만 복수 대상 유지. 모든 발화를 별도 작업으로 등록하지 않음 |
| 현재 논의 대상 | 선택 근거가 있을 때만 유지. 가장 최근 파일이나 단 하나의 저장 작업을 자동 선택 근거로 삼지 않음 |
| 출처와 확실성 | 사용자 명시·기존 수용 조건·에이전트 추론·미확인을 구별 |
| 적용 판단과 유효 범위 | 어느 대상·요청 맥락에서 판단했는지 유지. 과거 판단을 세션 전체의 영구 활성화로 취급하지 않음 |
| 전달 기록 | 전달한 원칙 ID·버전·내용 지문과 연결 상태. 실제 이해·준수를 보증하지 않음 |
| 미해결 질문 | 추가 확인이 필요한 사항. 단순히 질문이 있었다는 이유로 실패 처리하지 않음 |

기존 Task 파일은 선택적인 작업 정보로 참조할 수 있다. 파일의 존재나 배포만으로 미완료 상태·사용자 선택·현재 의도를 확정하지 않는다. 여러 작업을 참조할 때에는 개별 작업을 구별하고, 목표 목록을 작업 목록으로 간주하지 않는다.

세션 종료는 세션 연결의 종료일 뿐, 포함된 모든 작업이 완료됐다는 의미로 기록하지 않는다.

### 3.3 현재 요청

현재 요청의 원문·세션 버전·관련 맥락 참조·정책 지문을 해석의 입력으로 사용한다. 단순 요청은 메모리와 표준 입출력으로 처리할 수 있다. Task ID나 독립 완료 조건이 없어도 원칙 선택·응답이 가능해야 한다.

상태가 바뀌거나 검증 근거가 필요할 때만 관련 내용을 저장한다. 감사 목적의 요청 기록은 별도 기록 설정에 따르며, 전체 원문을 기본 세션 상태에 무제한 누적하지 않는다.

## 4. 사용자 흐름

1. 기존과 같이 프로젝트를 초기화하고 사용할 정책을 등록한다.
2. 기존 에이전트가 대화에 사용할 AMH 세션을 연결한다. 플랫폼의 세션 식별자를 제공받을 수 있으면 이용하고, 없으면 AMH가 만든 핸들을 에이전트가 유지한다.
3. 사용자는 평소처럼 요청한다. 에이전트는 요청과 실제 대화 맥락을 해석하고, AMH에서 연결 상태·정책 변경 여부를 가볍게 확인한다.
4. 기존 지침과 판단을 재사용할 수 있으면 작업을 수행한다. 조건이 달라졌다면 필요한 원칙을 추가·갱신하거나 현재 요청에서 적용을 종료한다.
5. 중요한 불확실성이 있으면 알고 있는 상태를 활용해 필요한 질문만 한다. 충돌하는 필수 조건을 임의로 해결하지 않는다.
6. 에이전트가 실제 작업을 수행하고 결과·실행한 검사·미확인 사항을 보고한다. 필요한 경우 세션에 연결된 검증 증거를 보존한다.

예: 오류 수정 → 수정 이유 설명 → README 반영 → 같은 코드의 추가 수정. 같은 세션 맥락을 활용하되, 설명 요청에 TDD를 강제하거나 README 작성에 코드 전용 원칙을 계속 적용하지 않는다. 이후 코드 요청에서는 앞서 적용을 끝낸 원칙도 다시 필요해질 수 있다.

### 모호한 이어하기

| 상태 | 평가할 판단 |
| --- | --- |
| 사용자가 특정 대상을 명시 | 그 대상과 최신 조건을 확인한 진행 |
| 하나의 저장 작업, 모호한 요청 | 대화 연결·기존 위임·위험에 근거한 진행 또는 확인. 어느 한쪽을 고정 정답으로 삼지 않음 |
| 복수 미완료 작업, 선택 근거 부족 | 후보를 확인하고 필요한 선택만 질문. 우선순위를 발명하지 않음 |
| 현재 논의와 다른 작업을 암시 | 과거 작업을 강제로 이어가지 않음 |
| 알려진 대상 없음 | 필요한 정보를 질문. 임의 목표를 만들지 않음 |

## 5. 재사용과 재평가

‘전에 전달했다’, ‘지금 적용된다’, ‘실제로 준수했다’를 구분한다.

재사용 판단은 에이전트가 현재 요청과 조건을 검토한 결과다. AMH는 세션·프로젝트·정책 버전·대상 범위의 일관성을 검사한다. 해시 일치는 의미상 적합성의 증명이 아니다.

| 상황 | 처리 |
| --- | --- |
| 맥락·정책·대상 범위가 유지되고 기존 판단이 현재 요청에도 유효 | 이미 전달한 원칙 본문과 판단을 재사용. 새 상태 파일이나 작업 계약을 만들 필요 없음 |
| 요청 목적·대상·요구가 변경 | 새로 필요해진 원칙과 적용이 끝나는 원칙을 해석 |
| 정책 추가·수정·일시 중지·사용자 정책 변경 | 지문 변경을 감지하고 영향 범위 재해석. 영향을 판단할 수 없으면 전체 재평가 |
| 새로 연결·재개·컨텍스트 축약 등으로 전달 상태가 불확실 | 현재 유효 조건을 다시 동기화. 과거 판단을 무조건 재사용하지 않음 |
| 필수 조건의 적용이 불확실하거나 선언된 충돌 존재 | 작업에 미치는 영향에 따라 확인·해결을 요구 |

중요한 제한:

- 재사용 검토가 이전에 선택한 원칙에만 한정되면 안 된다. 이전에 제외한 원칙도 새 요청에서 필요해질 수 있다. 조건 전체에 접근할 수 있어야 하며, 키워드 사전 필터로 필수 후보를 숨기지 않는다.
- 변경분만 제출하는 경로에서도 기존 판단의 버전·유효 범위를 확인하고 최종 선택 집합 전체에 대해 생명주기·의존성·충돌·수용된 요구를 검사한다.
- 현재 후보별 판단의 구조 검사를 없애고 의미 검증이 좋아졌다고 주장하지 않는다. 재사용 근거도 에이전트 판단으로 표시하며, 부적절한 재사용을 독립 평가에 포함한다.
- 정책 변경을 다른 프로세스가 할 수 있으므로, 최신성 보장을 유지하는 기본 경로에는 요청 처리 시 가벼운 읽기 확인이 필요하다. 확인 호출까지 생략하면 즉시 변경 감지를 보장할 수 없다는 한계를 명시해야 한다.
- ‘적용 종료’를 전달해도 모델의 과거 대화 기억을 지웠다는 의미는 아니다. 이후 실제 행동에서 과거 원칙의 잘못된 지속 적용을 평가한다.

## 6. 판단 근거와 프로토콜

새 세션 프로토콜은 현재 요청뿐 아니라 검증 가능한 맥락 참조를 지원한다. 출처는 현재/과거 사용자 발화, 명시적으로 수용된 조건, 정책 ID·버전, 확인된 작업 정보 등으로 구분한다. 원문 또는 내용 지문을 연결하고, 인용의 존재·바인딩과 의미적 타당성을 구별한다.

문서 속 인용이나 외부 자료는 사용자 의도·승인으로 승격하지 않는다. 에이전트가 요약하거나 추론한 조건도 사용자 수용 조건으로 자동 승격하지 않는다. 권한의 암호학적 인증을 제공한다는 주장은 추가하지 않는다.

프로토콜 입력은 프로젝트, 세션 ID·버전, 현재 요청, 관련 맥락 참조, 정책 지문에 바인딩한다. 다른 세션에서 만든 해석, 변경된 원문·정책·상태에 대한 해석은 적용하지 않는다. 재검토가 필요한 이유를 진단한다.

CLI 이름은 구현 시 확정하되 다음 기능을 제공한다.

- 세션 시작·연결·읽기·종료, 현재 정책 및 전달 상태 확인.
- 표준 입력/출력으로 요청과 해석 교환. 기본 경로에 요청·패킷·응답용 개별 영구 파일을 요구하지 않음.
- 재사용 또는 변경 제안 적용. 변경 제안은 예상 세션 버전 검사를 거치고, 기존의 명시적 로컬 적용·검토 방식과 연결.
- 세션별 지침 읽기, 필요한 검증의 명시적 실행, 기록 내보내기.

세션 핸들은 기존 에이전트가 관리한다. 핸들을 잃어버렸을 때 프로젝트의 ‘가장 최근 세션’에 자동 연결하지 않는다. 재연결 근거가 없으면 새 세션을 시작하거나, 기존 내용을 재사용하는 것이 작업에 중요할 때만 확인한다. 실행 플랫폼이 축약·재개 이벤트를 제공하지 않으면 그 감지까지 보장하지 않는다.

## 7. 파일·동시 실행·보존

제안 경로는 `.amh/sessions/<session-id>/state.json`과 필요한 경우의 `AGENTS.md`다. 상태 파일이 현재 세션 정보의 기준이며, 생성 지침은 파생물이다. 공용 `AGENTS.md`에는 연결 절차만 둔다. 다른 세션의 지침을 자동 탐색·로드하지 않는다.

세션 식별자는 안전한 내부 식별자로 생성/매핑한다. 외부 플랫폼 식별자를 그대로 파일 경로로 사용하지 않는다. 경로 탈출·심볼릭 링크·프로젝트 바인딩·수정된 생성 파일 검사를 유지한다. 세션 내 갱신은 버전 검사와 잠금으로 직렬화하고, 다중 파일 갱신에는 세션 범위의 복구 절차를 사용한다. 사용자 파일은 덮어쓰지 않는다.

- 세션 생성 시 필요한 최소 파일만 만든다. 판단·지침에 변화가 없으면 상태와 생성 지침을 다시 쓰지 않는다.
- 선택한 기록 수준에서 세션 이력을 남길 때에는 통합된 스트림을 사용해 요청마다 파일 수가 늘지 않게 한다. 로그는 상태의 두 번째 편집 원본으로 취급하지 않는다.
- 상세 stdout/stderr·실행 증거는 필요할 때만 별도 보존할 수 있다. 이 경우 파일 수가 증가하는 이유와 범위를 설명한다.
- 컨텍스트에 넣는 요약과 원본 실행 증거를 구분한다. 요약으로 원본 증거를 대체하거나, 요약된 추론을 사용자 승인으로 바꾸지 않는다.
- 상태 요약의 크기에 상한을 두고, 관련 없는 상세 내용은 참조로 남긴다. 초기 P0에는 자동 삭제를 기본 동작으로 추가하지 않는다. 정리·내보내기는 명시적 작업으로 두며 진행 중인 증거를 삭제하지 않는다.
- 이미 연결된 세션의 단순 요청은 추가 영구 파일이나 상태 쓰기 없이 응답할 수 있다. 모든 대화의 완전한 이력 보존을 기본 요구로 삼지 않는다.

파일 수를 줄이는 것과 로그를 충분히 남기는 것은 별도 선택이다. 같은 설정에서 변경 전후 파일 수·쓰기 횟수·전달량·검증 가능성을 비교한다.

## 8. 기존 구현과의 연결

| 대상 | 수정 내용 |
| --- | --- |
| `crates/amh-project/src/model.rs` | 세션 맥락·출처·범위 모델 추가. 기존 Task 입력 형식은 선택적 명시 계약으로 유지 |
| `crates/amh-project/src/natural.rs` | 요청 단독에서 세션 맥락 포함 해석으로 확장. 별도 버전의 프로토콜과 재사용/변경 판단 지원 |
| `crates/amh-project/src/resolve.rs` | 공통 선택 입력을 분리해 Task와 세션 양쪽에서 재사용. 정책 범위·필수 조건·의존성·충돌 검사는 유지 |
| `crates/amh-project/src/workspace.rs` 및 새 세션 모듈 | 세션별 상태·지침·계획·복구·진단 구현. 공용 브리지 갱신 |
| `crates/amh-project/src/verify.rs` | 선택적 세션 증거 연결. 명시적 Task 검증과 실행 명령의 명시적 선택 유지 |
| `crates/amh-cli/src/project.rs` | 세션 기능과 표준 입출력 경로 추가. 기존 명령과 적용 방식 보존 |
| `docs/agent-requests.md`, `docs/contracts.md`, `docs/p0.md`, `docs/architecture.md` | 구현된 범위·미확인 영역·이전 명령의 역할 설명 |
| `evals/`, `scripts/qualitative_eval.py`, 관련 테스트·CI | 여러 발화로 구성된 독립 평가 및 파일·동시성·관측 검사 확장 |

기존 task-scoped 정책과 `relations.applies_to`의 Task ID를 세션 ID로 바꿔 해석하지 않는다. 명시적 Task 참조가 있을 때 그 범위를 적용하고, 새 세션 범위는 구분해 정의한다. 단순히 `Task` 이름을 `Session`으로 바꾸거나 기존 필수 필드를 그대로 강제하지 않는다.

기존 `compile/sync/verify --task`는 호환 경로로 남긴다. 기존 배포 Task를 새 세션의 현재 의도로 자동 수용하지 않는다. 기존 생성 파일이 있는 프로젝트의 브리지를 갱신하되, 세션 경로와 명시적 Task 경로를 구별해 공용 파일의 내용이 다른 세션에 섞이지 않게 한다. 기존 정책·검증 기록·사용자 텍스트는 보존한다.

## 9. 과정 관찰과 독립 평가

현재 확보한 자료는 AMH 호출·출력, 초기/최종 파일, 실행자 최종 보고, 별도 최종 검사다. 하위 에이전트의 전체 세션 로그를 직접 확보한 것은 아니다. 현재 협업 인터페이스에 전체 로그 조회 기능이 없는 것과 다른 경로에서도 로그 확보가 불가능하다는 것은 구분한다.

후속 과정 평가 전에 실제 사용 환경의 지원되는 세션 내보내기·도구 호출 기록·실행 훅을 확인한다. 접근 가능한 경우 실행 시각·명령·출력·파일 수정·검사 시점의 코드/테스트 지문을 연결한다. 다른 세션이나 관련 없는 로그는 탐색하지 않는다.

로그를 확보하지 못하면 TDD 등 순서 기반 원칙의 준수는 미확인으로 남긴다. 도구 기록용 래퍼를 보강할 수 있으나 우회 가능성과 관측 범위를 명시한다. 실행자에게 과거 순서를 작성하게 한 자기 보고를 독립 로그로 취급하지 않는다. 로그가 있어도 관련 실패인지·검증이 목적을 충족했는지는 정성적으로 검토한다.

기존 파일럿의 S03은 ‘불필요한 재질문이 확정된 실패’라는 결론을 재검토한다. 저장된 작업·패킷의 맥락 누락·질문·작업 미수행은 관찰 사실로 보존한다. 재질문의 적절성은 현재 의도와의 연결 근거를 포함해 다시 판단한다. 기존 원자료와 평가자 의견은 바꾸지 않고 정정 설명을 추가한다. PR 본문·P0 문서·로드맵의 확정적 결함 표현도 이에 맞춰 조정한다. 이것이 곧 P0 완성이나 신뢰도 입증을 뜻하지는 않는다.

## 10. 검증 계획

### 구조·동작 검사

- 세션·프로젝트 분리, 오래된 버전·변경된 근거 거부, 동일 세션 동시 갱신 거부·복구.
- 활성 필수 조건·선언된 의존성/충돌·사용자 정책 변경·기존 Task 범위의 보존.
- 요청 원문만으로 별도 Task/완료 조건 없이 해석 가능한 경로.
- 변화 없는 후속 요청에서 파일 추가와 상태·지침 재쓰기 없음. 반복 요청 100회에서도 기본 영구 파일 수가 요청 수에 비례해 증가하지 않음.
- 기록을 켰을 때에도 통합 이력과 상세 검증 증거를 구분해 검사. 파일 크기까지 일정하다고 주장하지 않음.
- 기존 명시적 Task 흐름과 초기화·업그레이드·제거·사용자 파일 보존 회귀 검사.

### 여러 발화로 구성된 정성 사례

| 묶음 | 검토 내용 |
| --- | --- |
| 오류 수정 → 설명 → README → 다시 코드 수정 | 맥락 유지, 불필요한 개발 원칙의 지속 적용 방지, 필요한 원칙의 재활성화 |
| 같은 작업의 짧은 후속 요청 반복 | 중복 절차·전달 감소와 실제 요구 보존 |
| 같은 세션의 명확한 새 주제 | 이전 조건의 잘못된 전이·기존 논의의 손실 방지 |
| 한 저장 작업 + 모호한 요청 | 진행/질문 모두 근거에 따라 검토. 상태를 활용한 질문의 구체성 |
| 실제 복수 미완료 작업 + 선택 근거 유무 | 숨은 우선순위 강제 없이 적절한 선택·확인. 복수 목표로 대체하지 않음 |
| 명시적 대상 지정·대체·보조 요구 추가 | 현재 의도와 기존 수용 조건의 관계 |
| 이전에 제외한 사용자 정의 원칙이 뒤늦게 필요 | 선택된 원칙만 재검토하는 오류 탐지 |
| 중간 정책 변경·일시 중지·세션 재개 | 오래된 판단 거부와 전달 갱신, 과거 원칙의 실제 지속 적용 여부 |
| 두 세션의 동시 대화 | 세션 조건·생성 지침·증거의 혼입 방지 |
| 인용된 명령·에이전트 추론·사용자 수용 구분 | 요약·재사용 과정에서 출처와 권한의 잘못된 승격 방지 |
| 최종 산출물은 같고 수행 순서는 다른 코드 작업 | 로그가 있을 때 과정 차이 식별. 로그 부족 시 미확인 유지 |

각 사례는 이전 기획 대화와 예상 원칙 목록을 받지 않은 새 실행 세션에서 시작한다. 사례 내 후속 발화는 같은 세션에 순서대로 전달한다. 이 자연스러운 사례 내 대화는 검증해야 할 맥락 자체다. 실행자에게 미래 발화나 운영자용 검토 메모를 미리 주지 않는다.

별도의 평가자 2명이 초기 상태와 사용자 발화를 바탕으로 잠정 판단한 후 실행 기록을 검토한다. 합리적인 진행·질문·원칙 조합의 대안을 인정하고, 의견 차이와 추가 확인을 보존한다. 원칙 개수·정확한 선택 집합·진행 대 질문의 단순 비율을 합격 기준으로 삼지 않는다.

기계 검사는 구조·실행 사실을 확인하고, 의미·과정·과잉 절차는 정성적으로 검토한다. 파일 수·호출 수·시간·전달량은 사용성 비용 지표로 기록한다. 토큰 수는 실행 환경이 실제 값을 제공할 때만 기록한다. 이런 비용 수치를 의미적 정확도로 환산하지 않는다.

## 11. 구현 순서와 완료 조건

| 단계 | 산출물 | 단계 완료 기준 |
| --- | --- | --- |
| 1. 평가·설계 기준 정리 | S03 정정 설명, 범위/출처/세션 계약, 기존 입력의 호환 경계 | 저장 작업을 자동 현재 의도로 취급하지 않으며, 질문의 타당성을 유연하게 평가 |
| 2. 최소 세션 저장·선택·격리 | 상태 모델·읽기/갱신·세션별 출력·복구 | 새 세션·복수 세션·오래된 상태·기존 파일 보호 검사가 통과 |
| 3. 요청 처리와 브리지 전환 | Task 없는 자연어 경로·재사용/변경·표준 입출력 | 단순 요청에 필수 Task/완료 조건/개별 파일을 요구하지 않고, 필수 정책 검사를 유지 |
| 4. 재개·변경·선택적 검증 연결 | 최신성 확인·선택적 Task 참조·증거 연결 | 정책/대상 변경과 기존 명령 호환을 확인. 전달과 준수를 구분 |
| 5. 독립 대화 평가·문서화 | 새 실행·두 단계 평가·의견 차이·비용 비교·CI 결과 | 실제 실행한 범위와 미실행·미확인 영역을 공개하고 중요한 사례를 근거로 판단 |

코드·평가 인프라·실제 평가 증거·문서 변경은 책임별 커밋으로 분리한다. 기존 구현은 재사용할 수 있는 정책·검증·보호 기능을 유지하되 세션 모델에 맞추기 위해 필요한 구조 변경을 허용한다.

P0 완료는 자동 검사 통과만으로 선언하지 않는다. 자연어 요청에서 필요한 원칙을 찾고, 세션 맥락을 적절히 재사용하며, 사용자에게 불필요한 절차를 강요하지 않는지 실제 실행 증거로 검토한다. 파일 감소량이나 의미 정확도의 수치 목표는 측정 전에 임의로 약속하지 않는다.
