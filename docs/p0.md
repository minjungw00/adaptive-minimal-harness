# P0 walkthrough

## Set up a Git work tree

```sh
amh project add
amh project add --apply
amh pack list
amh pack show inquiry
amh pack install inquiry --apply
amh agent instructions
```

Copy the printed guidance into the agent's user-level settings. Use the agent
normally. Register another work tree with the same explicit `--id` if it should
share the same project policies. Use `--scope user` for personal policies shared
across registered work trees.

## Add and review a policy

```sh
amh policy add --id P-METRICS --text 'Compare like-for-like periods.' --when 'Comparing numeric results' --apply
amh policy list
amh policy change P-METRICS --pause --apply
amh history
amh rollback --revision 2
```

The last command previews the restoration. Add `--apply` after reviewing it.
To save an exact plan for a later invocation, append `--plan`, keep the output
as JSON, and pass it to `amh apply --plan FILE`.

## Export or move policy history

Export with `amh history --full` for project policy, or use `--scope user` for
personal common policy. Import a current-format export into an empty registry
with `amh policy import --file FILE`. The source file remains available as a
separate copy.

## Updating a pre-alpha installation

The `amh.policy-registry.v1` name remains while policy records now use the flat
shape documented in the [data contract](contracts.md). An older registry
containing nested `item` and `details` records will report a read error. Keep a
copy of that AMH home and use the previous executable to export its history.
For the new executable, set `AMH_HOME` to a new absolute directory outside Git
work trees, register the intended work trees, and add the reusable guidance you
want in the new registry. Keep task-specific goals and requirements with the
work. Review the new set before relying on it in your agent's settings.
