# P0 workflow and acceptance boundary

AMH provides policies to existing agents for explicitly registered work trees.
Its configuration, registries, and evidence are stored in the user's AMH home.

## Set up an existing project

From the Git work tree, preview and then register it:

```sh
amh project add --id report-project
amh project add --id report-project --apply
amh pack install --name inquiry --expected-revision 0 --reason 'Select inquiry policies' --apply
amh agent instructions
```

Add the printed instructions to your agent's user-level configuration. The
agent receives normal natural-language requests and uses
`policy discover`, `policy read`, and `policy resolve`. No policy is delivered
to an unregistered work tree. Registering an additional path with the same
project ID gives that work tree the same project-specific policies.
Personal policies shared across all registered work trees use `--scope user`.

## Explicit Task example

Use an explicit file with acceptance criteria or checks if the work needs them:

```sh
amh compile --task /path/to/examples/p0/writing.toml
amh verify --task /path/to/task-with-checks.toml
amh verify --task /path/to/task-with-checks.toml --run
```

Compilation returns instructions on stdout. Checks execute only on explicit
`--run`, from the Git work-tree root, and store their result and outputs under
`projects/<id>/evidence` in AMH home. Explicit tools run with the caller's
permissions. A changed task, registration or policy catalogue invalidates the
verification result. Verification and policy delivery do not establish
semantic compliance.

## Move an earlier installation

Register the work tree first. To copy an earlier policy history, point
`amh policy import --file /path/to/old/.amh/amh.toml` at a selected source and
review the plan. Apply with `--apply` or `amh apply --plan FILE`. Use
`--scope user` to import an earlier user-only registry. The destination must
be empty or already contain the identical history. A mixed legacy history is
rejected so that its revisions and scopes are preserved.

The importer copies event history and ignores the old private user-root
reference. Import the personal registry separately if needed. Review removal
of the old AMH block and artifacts as a separate repository change. AMH's
current workflow never applies that cleanup.

## Verification boundary

The automated suites exercise work-tree registration, scope, unchanged working
files, stale catalogue and plan checks, import, policy resolution and run
evidence. See the [evaluation notes](../evals/README.md) for observed agent
behavior and the limitations of those observations.
