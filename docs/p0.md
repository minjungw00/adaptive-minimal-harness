# P0 workflow and acceptance boundary

P0 is the lightweight path from user-owned policy to a task-specific agent
contract. Advanced signing/audit is optional and is not a prerequisite.

## Natural-language entry point

After initialization and optional pack installation, an existing compatible agent
retains one AMH session per conversation. Each request is interpreted with relevant
session context. Appropriate prior judgments/bodies can be reused; changes and
previously excluded principles are reconsidered. Simple requests need no Task or
invented completion criteria. Session state is a single atomic file, while current
instructions are emitted on stdout. See [agent integration](agent-requests.md).

Explicit Task contracts and one-shot Task interpreter adapters remain optional.
They can supply scoped work and executable verification when needed. Saved work
is information rather than proof of current intent. Several attachments do not
create a hidden priority or automatic choice.

## Explicit-task walkthrough

Choose an existing consumer project and run the installed `amh` there. Example
paths below refer to this repository's `examples/p0` directory.

```sh
amh init --id report > init-plan.json
# Review file ownership and before/after contents.
amh apply --plan init-plan.json
amh pack install --name inquiry --expected-revision 0 --reason 'Use the writing pack' --apply
amh policy add --file /path/to/examples/p0/requirement.toml --expected-revision 1 --reason 'Keep cost analysis' --apply
amh policy change --file /path/to/examples/p0/activate-requirement.json --expected-revision 2 --reason 'Activate accepted requirement' --apply
amh compile --task /path/to/examples/p0/writing.toml
amh sync --task /path/to/examples/p0/writing.toml --apply
amh doctor
```

Only `P-WRITING` and `R-COST` are selected. The Socratic principle is not activated
for a classified writing task. Existing AGENTS.md content remains outside an
identified shared block; `.amh/generated/AGENTS.md` carries the current task.
The source task file remains linked for drift diagnosis; editing its accepted goal or checks makes deployment stale. An agent must support AGENTS.md and read the referenced contract. AMH does not
assume every chat/model automatically loads files.

```sh
amh policy change --file /path/to/examples/p0/pause-writing.json --expected-revision 3 --reason 'Pause writing method' --apply
amh doctor # nonzero: the previous deployment is stale
amh sync --task /path/to/examples/p0/writing.toml --apply
```

The paused principle is removed from the generated instructions; `R-COST` remains.
Live sessions may retain old instructions and must be reloaded. `observed` stays
`unknown`; filesystem synchronization does not prove a model forgot a rule.

## Storage and review

- `.amh/amh.toml`: **user-owned canonical TOML event log**, project identity and
  optional user-registry reference. Current policies are replayed from it. There
  is no second editable current-state file. Use the CLI to preserve explicit history.
- `.amh/generated/AGENTS.md`: AMH-managed, task-specific adapter output.
- `AGENTS.md`: shared; only the exact AMH block is managed. Other text and existing
  permissions are preserved. Other instruction files are inventoried, not edited.
- `.amh/deployment.json`: rendered-source fingerprint and owned-output digest.
- `.amh/transaction.json`: temporary recovery journal, removed after success.
- `.amh/evidence/`: retained local verification records and tool output.
- `.amh.lock`: advisory lock serializing cooperating local writers.

Plans bind the canonical project root, source bytes, the selected task file, current user policy input,
and every output. Application recomputes the request and rejects stale or modified
plans. Generated-file edits, unknown ownership, malformed markers and symlinks
are refused. No force overwrite option is provided. Individual file writes use
synced temporary files and replacement; multi-file updates have a recovery journal,
not a claim of cross-filesystem/power-loss atomicity. `recover` first diagnoses,
then `recover --apply` restores previous bytes if there are no unrelated edits.

Registry rollback creates a new event with the earlier policy set. Restored
items get revisions above all previous versions. It does not silently rewind an
audit trail. Direct policy-file edits remain possible for the filesystem owner;
this is not authenticated policy enforcement or a sandbox.

## User, project, task and pack composition

Create a separate ordinary registry using `init`, register user-scoped policies
in it (or install a pack with `--scope user`), then explicitly reference its root with `init --user-root PATH` in each
consumer. Imports are read-only; changing a project does not write another
registry. User-registry changes can affect its consumers and are detected as
deployment drift. Recursive imports are refused. Duplicate IDs across scopes
require an explicit resolution instead of recency-based overrides.

Inline `Task.items` carry task-scoped policies. `relations.applies_to` restricts
an entry to explicit task IDs. Dependencies require another selected policy;
selected declared conflicts block compilation regardless of priority. Priority
only orders selected entries; it never removes an applicable MUST condition.
`supports`/`verified_by` are retained and rendered references, not semantic proof.

Packs `development` and `inquiry` are opt-in and editable using ordinary policy
operations. Pack ID, version and exact installed content are recorded in registry
events and exposed as lock digests. Reinstallation does not overwrite existing
identities. Custom packs use the same schema and require no core changes.
Automatic pack updates, nested pack dependencies and package distribution are
outside this initial implementation.

The explicit-task alternative uses caller-supplied classification. Set `classification_complete = true` only
after choosing the task's tags. If classification is incomplete, an unmatched
mandatory tag rule is uncertain and compilation stops. The natural-language path instead uses agent judgments against the catalogue and does not require tags. Independent semantic contradiction detection is not claimed. A character budget
fails rather than truncating mandatory conditions.

## Verification and regression cases

`verify` requires the exact deployed task. Without `--run`, commands remain
`not_run`. With `--run`, existing tools are invoked and their actual results
recorded against task/policy fingerprints. A changed deployment during verification
prevents an all-checks-passed result. Command success does not establish semantic
completion or process adherence. RED and GREEN invocations can be recorded with
their actual timestamps and expected exit codes; an independent assessment of
TDD ordering is not implemented.

| P0 acceptance behavior | Automated regression evidence |
| --- | --- |
| Conditional principle activation and simple-task minimality | Development/inquiry pack selection test |
| Policy content/details/metadata and lifecycle changes | Registry transitions and project workflow tests |
| Paused/retired policy removed from rendered output | Drift, pause and re-sync tests |
| ADD preserves existing core/support requirements | Requirement addition/replacement test |
| Explicit REPLACE deactivates the original | Requirement replacement and core transition tests |
| Socratic dialogue only when explicitly relevant | Inquiry tag selection test |
| TDD/refactoring definitions retain their intended verification obligations | Pack selection and rendered criteria; pilot outcomes observed, process order unverified |
| Actual checks distinguished from unexecuted claims | CLI/library verification success/failure tests |
| Reinstall/uninstall preserves user text and custom policy | Preservation and reinstallation tests |
| Safe update, concurrency rejection, recovery | Stale plan, tampered plan, symlink and partial transaction tests |

These tests establish deterministic P0 contracts. A [qualitative pilot](../evals/results/2026-11-17-pilot/report.md)
adds eight fresh-session executions and sixteen independent reviews without a
fixed selected-set oracle. It recorded a short continuation request asking for clarification despite a saved
Task. Whether that question was unnecessary is unresolved: stored work alone
does not establish current intent. The original categorical failure is corrected
in the report; raw evidence and reviewer opinions remain unchanged.
P0 completion is therefore not established by passing protocol tests. Broad
semantic measurement, rule-removal experiments and comparison against unassisted
agents remain unperformed. Native packages include documentation/examples and preserve executable permissions. Version tags prepare reviewable release drafts and checksums; public account-free installation requires publishing an approved release. License selection and signed release distribution
remain separate release gates; a planning checklist is not evidence of release.
