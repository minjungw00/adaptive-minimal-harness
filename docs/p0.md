# P0 walkthrough

## Set up a Git work tree

```sh
amh project add
amh project add --apply
amh pack list
amh pack show inquiry
amh pack install inquiry --apply
amh agent instructions
```

Copy the printed guidance into the agent's user-level settings. Use the agent
normally. Register another work tree with the same explicit `--id` if it should
share the same project policies. Use `--scope user` for personal policies shared
across registered work trees.

## Add and review a policy

```sh
amh policy add --id P-METRICS --text 'Compare like-for-like periods.' --when 'Comparing numeric results' --apply
amh policy list
amh policy change P-METRICS --pause --apply
amh history
amh rollback --revision 2
```

The last command previews the restoration. Add `--apply` after reviewing it.
To save an exact plan for a later invocation, append `--plan`, keep the output
as JSON, and pass it to `amh apply --plan FILE`.

## Export or move policy history

Export with `amh history --full` for project policy, or use `--scope user` for
personal common policy. Import to an empty registry using
`amh policy import --file FILE`. An existing `.amh/amh.toml` from the previous
repository-local version is also accepted. Import its common user registry
separately, with `--scope user`. Older files that mix incompatible scopes
require a manual decision about their contents.

Import preserves events and leaves the source and repository files in place.
Legacy task-scoped entries are preserved in history and management views.
Earlier work files are outside the current policy delivery flow.
